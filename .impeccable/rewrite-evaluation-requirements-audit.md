# 句子改写评估界面最终需求复核（2026-10-11）

依据：`9.  练习与生词（4）：句子改写评估界面.docx` 全文与内嵌最终图。保留文档 8 已完成的输入页、单题与草稿功能；不恢复已移除功能。依用户此前明确澄清，所有网页四个全局导航位于顶部，安装 Android 手机应用仍沿用原底部导航/键盘机制。

| 范围 | 实现 |
| --- | --- |
| §3–9 反馈设计 | 评估后答案是保留标点和换行的纯文本，标题右侧轻量铅笔修改。反馈共用一个区域，用标题/图标/浅分隔线区分亮点、建议、范例；移除内部白卡与重复边框。需要改进使用暖米色，其他真实级别使用品牌绿色，不将普通语言问题显示为严重红错。系统错误另用原 alert。推荐表达直接取 issues.correction，原表达取 issues.original，未虚构译文或建议。空数组/空白字段不生成空模块。 |
| §8–9 范例合并 | 相同或仅空白、弯直引号/外层引号格式区别的范例只显示一次，显示原始英文，不擅改 API 返回值；用词、否定、人称、大小写含义和不同标点有区别时，两种教学内容在同一模块下分别标记润色建议/参考范例。保守比较避免过度删除有意义内容。 |
| §10–12 修改状态 | 既有 store 增加 lastEvaluated（答案+结果）与 editing，并向后兼容旧 answer/evaluation 缓存；Dexie 表结构未变。进入修改不使有效结果/进度失效，但隐藏反馈。精确字符串不同才清除当前有效 evaluation，提示需要重新评估；原成功快照仍保留。改回完全相同答案恢复有效 evaluation。取消修改恢复原答案、反馈和进度，清除错误。 |
| §11 重新评估 | 原评估参数/后端提示词/评分逻辑保持。非空校验、pending 锁和晚返回绑定保留。结果通过已有结构校验后，成功快照与当前有效结果分开更新；失败保留草稿和旧成功快照，允许重试/取消。移除前端接口失败后用固定规则生成假评级的回退；网络/HTTP 错误不再伪装成成功。 |
| §12–13 进度/操作 | 进度只统计与当前答案精确对应的有效 evaluation；其他题不因导航受影响。成功后主按钮是下一题，正常走后一道真实题目；最后一题查整组状态，未完成则继续首个未完成题，全部有效已评估才显示完成练习（返回练习与生词），无新增总结页。上一题原次级样式和首题隐藏不变。 |
| §14 滚动 | 仅 pending→有效成功时向反馈标题轻量滚动一次；不是到最底部。等待期间用户 wheel/touchmove/滚动键操作后不强行自动滚动；减少动态效果使用 instant。重新打开已有结果不触发滚动。输入/修改继续沿用 visualViewport 可见性处理。 |
| §15–17 保存/适配 | 当前题目内容 key 保存到现有本地存储旁的独立 selection key，并留会话缓存；修改草稿与成功快照也持久化，切题/导航不丢失。保存失败提示/重试、卸载保护保留。反馈自然页面滚动，无固定高度或嵌套滚动条；全站导航不改版。 |

验收：

- 隔离预置数据及可控制的模拟响应，不发送真实 AI 请求，不修改用户题目/答案/结果。先检查 1280×720 默认桌面，再在可见验收标签核对真实 innerWidth 后测试 390×844 手机。
- 修改未输入：1/4 不变，反馈隐藏、原答案恢复为输入框；修改文字：0/4，提示需要重新评估；取消恢复完整原答案（包括换行）、原反馈及 1/4。
- 模拟失败：0/4，错误 alert、改后文字仍在、无假反馈；取消可恢复。模拟有效成功：1/4，Good 新评级，输入框转纯文本，无残留旧评级，出现下一题；自动滚动发生一次。
- 下一题是空草稿，不自动请求；最后第 4 题成功后，其他题未完成时显示继续未完成题目，进入第 2 题。补齐第 2/3 题后第 4 题显示完成练习，点击返回上级。步骤显示真实 4/4，已有记录保留。
- 320×480、24px 根字体长反馈高 3885px，overflow-y:visible，页面无横向溢出，下一题按钮仍在正常文流；768×1024 大字号、1440×900 正常字号均无横向溢出；桌面页面宽 704px。
