# Android 旧入口迁移验证

状态：待真机验证。现有连接不能直接操作用户手机；桌面 Chromium 小屏检查和 worker 单元测试不是 Android 真机证据。

保留原有主屏幕图标，不卸载、不清除 Chrome 网站数据，不重新安装。学习数据保存在设备本地，清除网站数据可能造成数据丢失。

## 真机步骤

1. 联网后从旧图标打开，记录是否正常进入、当前短文标题、生词本数量、历史短文数量。数量应以同一篇当前短文比较；本轮列表已改为只显示当前短文已添加词条。
2. 在生成输入框输入“迁移测试，请保留”，不要生成。保持页面打开一两分钟，再切换其他页面返回，确认没有突然跳转且文字保留。
3. 把入口退到后台再回来，检查文字和当前词条；在同一标签页内刷新后检查草稿及复习位置。彻底关闭进程后不承诺恢复 sessionStorage 中的临时草稿。
4. 记下已有的一个词条状态与一篇历史短文，关闭此网站所有窗口后重新从旧图标联网打开。检查能进入、无白屏，已保存词条状态和历史短文仍在；最新界面可出现但不得清空学习数据。

回报：Android 版本、Chrome 版本、旧图标打开方式、各步通过/失败；失败时附截图。无需提供账号、密钥或完整学习数据库。

## 已有证据与限制

- worker 回归测试验证迁移脚本不强制 skipWaiting、不导航活动窗口，激活时只注销自身。
- 当前代码不新增 worker 注册，旧缓存清理不删除 Dexie 学习数据库。
- 小屏布局检查使用桌面 Chromium，不能证明 Android 实际触控、系统任务恢复或旧入口迁移通过。
- 若旧安装仍展示旧界面，先记录现象，不通过清数据、卸载或重装来掩盖迁移问题。
